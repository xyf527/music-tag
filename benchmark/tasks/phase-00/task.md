# Phase 00 — 音频标签技术验证与工程基线

## 目标

建立可运行的 Java 17 / Spring Boot 3.x / Maven 工程基线，并用可复现的 PoC 验证 V1 核心音频标签技术是否真实可行。本阶段只做技术验证和能力矩阵，不实现正式业务页面、数据库表、批处理或部署。

开始前完整阅读：

1. `README.md`
2. `BENCHMARK.md`
3. 当前工具入口文件：Codex 读取 `AGENTS.md`，Claude 读取 `CLAUDE.md`
4. `benchmark/prompts/candidate-common.md`
5. `docs/Music-Tagger-V1-开发设计文档.md`
6. 本任务文件

## 共同配置

- Baseline: Git tag `benchmark/phase-00-base`（启动前必须确认当前 HEAD 与该 tag 一致）
- Candidate Model: `gpt-5.6-luna`
- Reasoning Effort: `medium`
- Terminal: Ghostty
- Target Java: 17

## 第一响应要求

先只输出简短实施方案，必须包含：

- 预计新增或修改的文件。
- 拟验证的标签库版本及选择依据。
- MP3、FLAC、WAV 的验证矩阵。
- 音频原件保护与测试副本方案。
- 自动测试、人工播放器验收、风险和停止条件。

输出方案后等待用户确认；收到确认前不得修改代码、安装依赖或生成工程。

## 用户确认后必须完成

- 创建最小 Maven / Spring Boot 工程，锁定 Java 17 和明确依赖版本。
- 将音频标签库封装在最小适配层中，PoC 代码不得泄漏到未来业务层契约。
- 对 MP3、FLAC、WAV 分别验证：读取基础标签、写入标题/歌手等文本字段、封面、歌词或格式实际支持的等价字段、重新读取校验。
- 所有写入只发生在临时副本；验证原始测试文件 SHA-256 不变。
- 验证写入后音频仍可解析；能够可靠比较音频流或解码内容时执行并记录，不能可靠执行时如实说明。
- WAV 的 ID3、RIFF INFO、歌词和封面能力必须单独记录；不支持的能力写明限制，不得伪装通过。
- 形成机器可执行测试和人工播放器验收说明。
- 生成格式能力矩阵，区分 `VERIFIED`、`UNSUPPORTED`、`FAILED`、`NOT RUN`。

## 测试素材规则

- 不得提交任何音乐、封面或歌词测试文件。
- 测试素材位于 Git 仓库外，通过环境变量或命令参数指定。
- 两个候选使用同一份只读素材源，各自在临时目录生成工作副本。
- 若当前没有合规样本，可以生成原创短音调作为临时技术样本，但必须记录生成命令、编码器和格式；真实播放器人工验收仍需如实标记。

## 明确不做

- 不实现正式 UI、上传页面、批量导入、匹配流程或完整领域模型。
- 不创建 MySQL 表、Flyway 正式业务迁移、MinIO、Docker Compose 或 M710q 部署。
- 不实现 URL 下载、第三方平台抓取、AI、Redis、MQ、微服务或 Kubernetes。
- 不声称尚未真实验证的格式可用。

## 验证要求

- 执行 Maven 全部自动测试和构建。
- 记录 Java、Maven、标签库和测试工具的实际版本。
- 记录每种格式每项能力的真实结果和失败信息。
- 检查仓库中没有媒体文件、Secret、构建产物或 IDEA 私有配置。
- 完成后提交到当前候选分支，按 `benchmark/templates/candidate-report.md` 汇报并停止。

## Judge 关注点

- 两边是否从相同起点、相同任务和同一候选模型开始。
- 是否真实验证依赖 API，而非根据文档或猜测声称支持。
- 是否保护原件并可复现地校验读写结果。
- 是否诚实处理 WAV 等格式差异。
- 是否保持 Phase 00 范围，没有提前建设完整产品。
