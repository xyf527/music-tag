本阶段只有 Codex 继续开发。Claude 已淘汰，不得读取、搜索、比较、引用或复制 Claude 的目录、分支、提交、报告、会话和实现。

## 必须完成

### 1. 真实格式能力验证

- 使用仓库外原创或工具生成的合法 M4A、OGG Vorbis、Opus 样本进行验证，不提交媒体文件。
- 分别验证：格式识别、已有标题/歌手/专辑读取、标签写入、写后重读、封面 KEEP/SET/REMOVE、歌词 KEEP/SET/REMOVE、输出文件可解码与可播放。
- 对容器、标签规范或当前库不支持的能力必须明确记录为 `UNSUPPORTED`，返回稳定错误码和中文说明；禁止静默成功、复制原件冒充成品或仅按扩展名声称支持。
- M4A、OGG 和 Opus 分开记录，不得用其中一种格式的结果推断另一种。
- 更新格式能力矩阵，保留 MP3、FLAC、WAV 的既有真实结论，WAV 歌词不支持继续作为明确能力边界。

### 2. 适配器与注册结构

- 新格式通过现有音频 Provider/Adapter/Registry 扩展；业务用例、单曲与批量编排不得新增按格式不断扩张的中心 switch/if 链。
- 格式探测结合实际内容与受控扩展名，拒绝空文件、伪造扩展名和不匹配容器。
- 每个适配器公开细粒度能力，例如标签、歌词、封面和输出支持；页面、API 和批量流程依据同一能力来源决定可用操作。
- 新增格式不得复制 Phase 01/02 的版本、任务、报告、备份、生命周期或下载逻辑。

### 3. 单曲、批量与报告闭环

- 只有通过真实验证的格式才能进入对应单曲和批量入口；部分能力不支持时页面必须在执行前禁用或提示。
- 对已开放的新格式完成上传、读取、预览、修改、写后验证、新版本、下载、JSON 报告、批量执行、ZIP 和失败重试。
- MinIO 开启与关闭两种模式均不改变本地处理结论；新格式成品及实际绑定的歌词、封面进入既有备份流程。
- 报告记录格式、实际执行能力、输出哈希、验证结果和稳定错误码，不泄露服务器路径或 Secret。

### 4. 兼容性与数据库演进

- MP3、FLAC、WAV 现有行为不得回归；Phase 01 至 Phase 03 的关键自动测试继续通过。
- 如需数据库变化，只能新增下一版 Flyway 迁移；不得修改 V1 至 V5，不得删除或重建数据库。
- MySQL 仍是任务事实来源，文件和 MinIO 状态继续服从既有恢复、生命周期和磁盘保护规则。
- 不为了宣称支持格式引入不受维护的二进制、平台专属绝对路径或运行时下载行为。外部解码工具如确有必要，必须固定、检测、文档化，并在镜像与 M710q 上复现。

### 5. V1 最终文档与部署

- 更新 README：实际支持矩阵、明确不支持项、单曲/批量用法、Docker/Toolkit 部署、外部 MySQL/MinIO、备份、恢复、升级、健康检查和常见错误。
- 提供 `docs/Phase04-Candidate-Report.md` 与最终人工验收清单，所有结论与实际测试一致。
- 发布包继续不包含 `.env`、`application.yml`、真实媒体、凭据、数据库、IDE 配置或个人路径。
- 保持单实例限制；只说明未来 K8s 单副本迁移前提，不新增 Kubernetes、认证、微服务或分布式组件。

### 6. 自动验证

至少覆盖：

- M4A、OGG、Opus 各自的真实读取和已声明写入能力。
- 写后重读、音频可解码、原件哈希不变、成品独立。
- 封面与歌词三态；不支持能力必须明确拒绝。
- 内容与扩展名不一致、损坏文件和伪造格式。
- 单曲、混合格式批次、部分成功、重试、ZIP 和 JSON 报告。
- 新格式的版本链、MySQL 持久化、MinIO 状态、生命周期和下载边界。
- MP3、FLAC、WAV 回归以及格式注册扩展性测试。
- Docker 镜像、Compose、非 root、健康接口和发布包回归。

必须实际运行 Java 17：

```text
mvn clean verify
mvn package
git diff --check
```

## 人工验收

1. 分别用真实 M4A、OGG、Opus 检查页面展示的能力与实际操作一致。
2. 对支持的字段执行修改并下载，用播放器确认可播放，再重新上传确认标签、歌词和封面。
3. 对明确不支持的操作确认执行前提示或稳定拒绝，不生成虚假成功版本。
4. 创建包含 MP3、FLAC、WAV、M4A、OGG、Opus、损坏文件和伪造扩展名的混合批次，检查分类、部分成功、重试、ZIP 和报告。
5. 在 MinIO 开启状态检查新格式备份状态与对象；短暂停止 MinIO，确认本地成功不回滚且恢复后可重试。
6. 通过 Alibaba Cloud Toolkit 升级 M710q，确认版本 commit、MySQL 历史、既有任务、持久文件和健康接口。
7. 重建应用容器并检查历史下载；在已有上一版本的前提下执行一次失败部署或手动回滚验收。

## 明确不做

- 不实现 URL 下载、第三方抓取、AI 自动识别、在线播放器、转码中心、认证、外网发布、Redis、MQ、微服务、Kubernetes manifest 或 Helm。
- 不因格式标签能力不足而擅自转码音频。
- 不修改或删除用户已有数据库、MinIO 对象和持久化目录。
