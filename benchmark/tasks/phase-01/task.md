# Phase 01 — 单曲编辑最小闭环

## 目标

在 Phase 00 已验证的音频能力上交付一个可实际操作的单曲编辑闭环：上传一首音乐，读取并预览现有信息，选择性修改标签/封面/歌词，在工作副本上处理并校验，保存为新版本，持久化任务记录，最后下载成品和 JSON 报告。

本轮指令已经构成明确实施授权。完成启动核对后直接开发，不再要求用户二次确认；只有需求存在无法从文档判断的实质冲突或外部条件完全阻塞时才提问。

## 必须完成

### 1. 可运行的模块化单体

- 保持 Java 17、Spring Boot 3.x、Maven。
- 将全部项目自有主代码和测试代码迁移到根包 `com.xin.musictag`，目录与 `package` 声明一致；不得残留 `com.example.*` 项目代码。
- 代码至少清晰分为 Web/DTO、application/use case、domain contract/model、infrastructure/persistence、audio adapter；包名可以不同，但职责必须可辨认。
- 不允许把上传、标签读写、数据库、文件发布、报告生成全部堆在一个业务类或 Controller 中。
- Phase 00 PoC 可以重构或复用，但不得留下两套互相冲突的正式实现。

### 2. 单曲 Web 流程

- 首页提供“单曲编辑”入口。
- 上传一个 MP3、FLAC 或 WAV；LRC 和 JPEG/PNG 封面均为可选。
- 上传后展示原文件名、实际格式、大小、时长及可读取的现有标签。
- 编辑页支持标题、歌手、专辑；歌词和封面支持 `KEEP / SET / REMOVE` 三态。只修改一个字段时，其他已有字段必须保留。
- 提交前展示变更预览，明确列出保留、修改、删除和格式能力警告。
- 执行后展示状态、错误阶段、错误码、成品版本、下载入口和 JSON 报告入口。
- WAV 对 Phase 00 已证明不支持的字段必须在预览阶段提示并拒绝该项，不能静默丢失或伪装成功。

### 3. 原件、版本与文件安全

- 原件不可变；所有写入只发生在任务工作副本。
- 成功处理后发布新的成品版本，不覆盖原件或旧成品。
- 写后重新读取并核对请求修改的字段，确认音频仍可解析；原件 SHA-256 必须保持不变。
- 上传、工作、成品、报告目录均从配置读取，禁止在响应或页面暴露服务器绝对路径。
- 校验扩展名与实际音频/图片内容，拒绝空文件、目录穿越文件名和超出配置上限的上传。
- 失败时清理或隔离未发布工作副本，保留可诊断但不泄露绝对路径的错误记录。

### 4. MySQL 与 Flyway

- 使用 MySQL 8、Flyway 和业务 Repository 接口；业务用例不得直接依赖 Mapper 或 JDBC。
- 至少落地本轮需要的资源、处理任务/条目和音乐版本记录；字段可按当前闭环精简，但必须支持状态、错误、哈希、存储标识、版本关系和时间。
- MySQL 是状态事实来源；JSON 报告由数据库中的任务结果生成或可重建。
- 数据库连接全部通过环境变量/配置注入，不提交凭据。
- 禁止在源码、配置、文档、日志、测试或报告中写入真实 IP、主机名、密码、Token、Key、连接串、SSH 材料或个人部署路径；只能引用环境变量或使用明显无效的占位符。
- 两个候选使用独立数据库：`music_tag_codex`、`music_tag_claude`，不得共用 schema 或 Flyway 历史表。

### 5. 自动测试与可验收产物

- 单元测试覆盖三态更新、未修改字段保留、格式能力拒绝、错误分类和路径/文件名安全。
- 集成测试覆盖上传 → 预览 → 执行 → 数据库记录 → 新版本 → 下载 → JSON 报告的最小闭环。
- 使用仓库外生成的原创样本；不得提交音乐、封面或歌词文件。
- `src/test/` 测试源码必须提交；本地生成的测试媒体、临时数据和报告只能写入已忽略的根目录 `/test/`、`/tests/`、`/test-output/`、`/test-results/`、`/.test-data/` 或仓库外目录。
- 至少对 MP3、FLAC 完成成功闭环。WAV 按候选已验证能力完成支持或明确的可定位拒绝。
- 提供一个命令或脚本，将可人工检查的处理后文件和 JSON 报告稳定输出到仓库外指定目录；测试结束不能自动删除这些验收产物。
- 执行 Maven 全部测试和打包，记录真实结果。

- 应用端口通过 `SERVER_PORT` 覆盖，代码中不得写死候选身份。
- 本地同时运行建议：Codex `18081`，Claude `18082`。

- 数据库通过 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD` 配置。

## 人工验收

1. 用浏览器完成 MP3 和 FLAC 的上传、预览、仅改单字段、替换/删除歌词或封面、执行与下载。
2. 用播放器/标签工具打开下载成品，确认可播放且请求的标签生效，未修改字段保留。
3. 对照哈希确认原件未变，再次编辑同一资源时产生新版本而非覆盖旧版。
4. 下载 JSON 报告，确认与页面和数据库状态一致，且不含服务器绝对路径或凭据。
5. 尝试不支持的 WAV 操作、伪造扩展名、空文件和危险文件名，确认得到清楚且安全的错误。
6. 在 IDEA 中检查职责是否分层；若除启动类外仍只有一个承担全部功能的主要类，本轮代码结构门禁失败。

- 真实端到端功能优先于类数量；但单个主要类承载全流程、缺少要求中的层次或无法提供处理后成品，判定本轮不通过并进入修复。
